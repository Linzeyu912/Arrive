# 产品路线图与后续规划

> 当前状态核对截至：2026-09-06。本文保留长期方向；日常进度、问题与跨模型交接统一见 [开发进度与模型交接](./开发进度与模型交接.md)。

## 1. 产品主链路

Arrive 将信息传递拆成三个边界清晰的阶段：

```text
表达者的内在思考
        ↓
   编码 Encoding          ← 当前开发重点
        ↓
共享语义表示 Semantic Packet
        ↓
   传递 Transmission      ← 先定义数据契约与完整性
        ↓
   解码 Decoding          ← 编码稳定后开发
        ↓
接收者能够进入的表达与理解
```

- **编码**回答“表达者究竟想传递什么”；
- **传递**回答“这份含义如何在通道中保持完整、可追溯”；
- **解码**回答“怎样按照具体接收者的知识、语言和思路，使其准确理解”。

编码、传递与解码作为信息交流的过程框架保留。产品重点首先是编码，其次是解码；先让编码结果稳定、忠实且可验证，再开发接收者侧的解码能力。

这是语义职责的分层，不强制规定软件的部署顺序。如果解码运行在接收者一侧，可以先传递 `SemanticPacket` 再解码；如果由发送侧服务代为生成接收者适配文本，则先调用解码模块生成沟通表示，再通过物理通道发送。两种实现都必须保持解码结果可追溯到同一个编码版本。

## 3. 当前主线：编码闭环

### 3.1 当前纵向切片：忠实采集与镜像确认

两种输入最终统一形成带时间的个人素材：

```text
外部来源 → 冻结来源快照 → 使用者对全文或具体位置批注 ┐
                                                         ├→ Material(MNNN)
使用者直接输入 → 原样保存，无需额外批注               ┘
                                                              ↓
                                                    pending_mirror
                                                              ↓
                                             LLM 镜像候选 + 使用者确认/纠正
                                                              ↓
                                       eligible_as_evidence / semantic_check
```

所有原始输入立即保存，但“保存”与“理解确认”分开。镜像候选不能覆盖原话；未经确认的个人素材可以回看，但只留在待处理区，不得进入正式思考地图。

外部批注必须锚定不可变来源快照。锚点支持全文、章节、段落、句子、文本范围、页码、音视频时间段或画面区域，同时保存 `source_snapshot_id`、快照哈希与相应定位信息，避免来源更新后定位漂移。

通用契约允许文字、音频、图片、视频、文档和其他载体。首个软件纵向切片先完成文字直接输入与网络文章批注，再以相同模型增加转写、OCR 和其他载体适配器；路线图不会把尚未实现的适配器描述为现有能力。

每条导入、批注、直接输入、镜像和确认记录都有带时区的公共审计时间 `recorded_at`；访问和抓取另记 `accessed_at`、`captured_at`。个人思想所属时间使用可空的 `effective_at` 和时间精度表达：已知是当下时可等于录入时间，未知时保留为空。思考地图需要明确标记时间回退；文章发布时间不等于使用者产生想法的时间。

### 3.2 已确认机制：按需歧义检查与关键词语义确认

镜像确认后始终运行歧义检查。普通词只有在存在多种合理解释，且不同解释会改变命题、关系、范围、强度、指代、时间或后续复用结果时，才向使用者提问。一旦一个词被使用者主动标记，或将成为关键概念、命题核心词或共享语义锚点，即使只有一个明显候选含义，也必须由使用者确认，LLM 不能自动放行。

```text
已确认镜像
    ↓
高影响歧义与关键词扫描
    ├─ 无实质歧义且无关键词 → semantic_ready
    └─ 有关键歧义或关键词 → 展示原句、共享含义候选、个人旧义与 LLM 候选
                              ↓
                         使用者处理词义
                              ↓
               单义 / 多义 / 当前特例 / 沿用旧义 /
               确认未知 / 不需建模 / 暂缓
```

每轮默认只询问一个最高影响歧义；关键词语义卡可以批量展示，但默认最多三个。确认结果必须带具体出现位置、适用范围、时间与不可变版本；以前确认过的含义只有在适用范围相同且没有冲突时才复用。

准入分为两层：镜像确认后的素材可以作为证据节点进入正式思考地图；依赖关键词语义的概念或命题，只有相关问题已经处理，才能标为已确认或冻结进 `SemanticPacket`。确认多义、确认刻意模糊或确认目前未知也属于已处理；`pending` 和 `deferred` 只阻塞依赖节点。

当前软件仍先交付忠实采集与镜像确认，再实现本机制。协作机制阶段五至八继续暂缓细化。

### 3.3 编码结果契约

下一阶段首先定义稳定的 `SemanticPacket`（暂定名）。它至少包含：

- 原始素材引用及需要保留的原话；
- 表达者确认的命题；
- 关键概念的个人含义；
- 关键词出现位置与已确认的含义版本；
- 可追溯的共享语义锚点；
- 个人含义与共享含义之间的差异；
- 支持、因果、条件、冲突和例外关系；
- 事实、推测、未知项和置信状态；
- 表达目的、边界和不得进入输出的内容；
- 编码版本、确认状态和时间。

编码产物不直接针对某一个接收者措辞。它保留个人含义，以可解释的公共语言描述，并明确没有共识的差异，供后续传递和多种解码方式复用；不是一套要求所有人接受的统一定义。

### 3.4 共享语义锚点

目标不再表述为“大家统一认可的解释”，而是**保留个人含义，用可解释的公共语言表达；没有共识的地方明确说明差异**。共享锚点仅帮助解释，不优先于已确认的个人含义，可以来自：

- 标准、法律定义或权威术语；
- 有可靠来源支持的领域共识；
- 特定社群或专业语境中的稳定用法；
- 日常语言中的稳定常用含义；
- 对争议概念并列保存的多种主要解释。

这些类别不是固定优先级。系统先依据当前领域、语境、表达目的和适用人群选择候选，再比较来源可靠性、时效性和解释覆盖范围。法律定义只在相应法域和法律语境中具有特殊权重，不能自动覆盖日常或个人语境。

每个锚点记录定义、来源、适用范围、版本、获取时间和共识状态。表达者自己的特殊含义作为“个人语义差异”独立保存，不冒充共享锚点。找不到真实共识时必须明确标记，不用流畅措辞制造虚假统一。

### 3.5 编码循环

```text
原始输入
  → 分段与类型标注
  → 镜像确认
  → 按需歧义检查与关键词语义确认
  → 命题与关系建模
  → 连接共享语义锚点
  → 标出个人语义差异
  → 表达者校准
  → 冻结一个编码版本
```

模型只能提出候选编码。未经表达者确认的归纳、关系和概念映射不能冒充最终含义。

### 3.6 编码验收指标

- **忠实度**：表达者是否仍然认得；
- **覆盖度**：重要素材、矛盾和边界是否遗漏；
- **可追溯性**：每个命题和解释能否回到来源；
- **共享可解释性**：陌生读者能否依据语义锚点理解关键概念；
- **差异透明度**：个人用法与常用含义是否分开；
- **不确定性诚实度**：未知和争议是否被保留；
- **版本稳定性**：修改是否通过新版本发生，而非静默覆盖。

## 6. 通用能力复用与试用门槛

以下是候选与规划，不表示已经集成，也不因开源就自动满足本项目需求：

| 候选 | 用途 | 当前决定 |
| --- | --- | --- |
| W3C Web Annotation | 标准化来源目标、原句与上下文定位 | 采用其建模方向，结合不可变快照设计；尚未实现兼容性 |
| Hypothesis | 网页批注交互 | 评估嵌入与本地数据适配，不直接启用外部托管保存 |
| Memos | 快速采集入口 | 保留接入候选，先测试是否符合原样保存、时间与归属规则 |
| Argdown | 论证表示和论证图输出 | 待实际思想样本验证，不能用论证图取代全部思考地图 |

接入前检查具体版本及依赖的许可证、数据流向、导出能力、时间与来源信息保真、维护成本。只有试用证明符合主线且节省总体成本时才采用；不适合时可放弃，不让外部工具反向决定个人含义机制。真实个人试用材料与评估记录在 Git 忽略的数据目录；公共论文索引、原创研究摘要和指导方法可进入 [研究依据](./research/README.md)，全文副本另查再分发许可。

LLM 的职责包括帮助组织零碎想法、提出更准确的表达候选，并在后续支持接收者适配；不是在所有环节实时介入。具体介入策略仍是开放设计问题，阶段五至八不因这些候选提前进入完整实现。
