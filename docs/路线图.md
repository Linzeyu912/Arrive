# 路线图

## v0.x：验证思考转译流程

目标：使用作者自己的真实思绪作为第一套样本，建立稳定的采集、澄清、建模和校准流程。

- [x] 明确“抵达 / ARRIVE”的项目定位
- [x] 建立思考转译协作机制 v0.1
- [x] 建立思绪、表达任务、思考地图和校准模板
- [ ] 完成第一批未经整理的思绪采集
- [ ] 完成至少 10 次完整转译记录
- [ ] 覆盖对话、书信、文章三种不同输出媒介
- [ ] 找出最常见的失真来源
- [ ] 根据使用结果修订框架至 v0.2

阶段产物：真实样本、转译记录、失真类型清单和框架修订记录。

## v1.x：形成可复用方法

目标：让框架能够由作者之外的人理解和使用，并明确其边界。

- [ ] 提炼最小转译流程
- [ ] 形成高信息价值问题集
- [ ] 建立个人语言档案方法
- [ ] 设计接收者理解测试
- [ ] 增加失败案例、反例和适用边界
- [ ] 邀请少量使用者参与测试

阶段产物：思考转译手册、案例库、校准清单和隐私规范。

## v2.x：构建最小产品

目标：把经过验证的方法转化为可交互的工具。

- [ ] 明确优先用户与高价值场景
- [ ] 设计从自由输入到候选表达的交互流程
- [ ] 支持版本对比、原话保护和含义确认
- [ ] 支持不同接收者和表达媒介
- [ ] 建立隐私、安全和数据导出机制
- [ ] 验证工具是否真正减少表达失真

阶段产物：可以完成一次端到端思考转译的最小可用产品。

## v3.x：开放与扩展

目标：让更多人贡献方法、案例和改进，同时保护个体语言的独特性。

- [ ] 建立贡献规范和匿名案例格式
- [ ] 支持不同语言、文化和表达习惯
- [ ] 建立框架版本兼容与迁移规则
- [ ] 探索对话、教育、协作和长期思想记录场景

## 近期下一步

1. 将第一批未经整理的想法放入 `content/inbox/`。
2. 使用 `templates/思绪采集.md` 保留原始材料。
3. 使用 `templates/表达任务.md` 明确第一次真实表达任务。
4. 建立思考地图并生成候选表达。
5. 完成第一次双向校准，记录框架的有效与无效部分。
