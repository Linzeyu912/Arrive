# 外部来源库

这里保存对外部思想来源的可追溯记录，包括网络文章、书籍、视频、播客、演讲和对话。

“保存来源”包含四个层次：

1. **原始快照层**：在权利允许或使用者直接提供时，本地保存带版本的原始内容并计算哈希；
2. **来源身份层**：保存原始链接、作者、标题、平台、发布时间、访问日期、版本线索和处理记录；
3. **使用者批注层**：保存使用者针对全文或具体位置写下的思考、定位信息和时间；
4. **思想转译层**：保存文章结构、详细摘要、关键命题、概念关系、必要短摘以及使用者对它的认同或质疑。

来源分为公共项目研究和个人来源库。公共文献、项目指导方法与不含个人数据的研究分析可放在仓库 `docs/research/`，以 `REF-NNNN` 编号，按版权许可决定是否内置全文。个人来源库的全文、来源卡、阅读摘要、命题与回应仍保存在仓库外的 `ARRIVE_DATA_DIR`，沿用 `SRC-NNNN`；用户批注不能随公共文献一起上传。完整边界见 [软件与数据隔离规范](./软件与数据隔离规范.md)。

公共研究记录至少包含标题、作者、链接、版本或日期、核查时间、原创摘要、项目方法关联、证据局限与再分发状态。不能把个人来源卡改个编号直接发布；应依据公共来源重新整理，去掉个人立场、实例编号、数据路径与测试痕迹。项目研究引用不需要先成为用户个人命题。下文的批注、镜像和立场流程面向个人来源库。

## 分层保存原则

```text
ARRIVE_DATA_DIR（不提交）
├── raw/sources/
│   └── 用户提供或有权保存的不可变来源快照
│       └── 记录版本、抓取时间、字节数与 SHA-256
├── sources/
│   └── 来源卡、元数据、命题与处理记录
└── materials/
    └── 带来源位置的使用者批注（MNNN）
```

个人来源库中的原始快照、来源身份、使用者批注与思想转译各层在逻辑上分开，仍属于使用者数据。公共项目研究单独整理，不混入这些私人记录。

## 目录

- `web/`：网页和微信公众号文章；
- `books/`：书籍和长篇出版物；
- `media/`：视频、播客和演讲；
- `INDEX.md`：全部来源的统一索引。

## 来源编号

来源使用稳定编号：

```text
SRC-0001
SRC-0002
```

编号分配后不重新排序。文件名采用：

```text
SRC-0001-简短标题.md
```

标题尚未取得时使用平台或临时说明，待补全后可以修改文件名，但编号保持不变。

同一来源的每次抓取或导入使用不可变快照版本：

```text
SRC-0001/V001
SRC-0001/V002
```

成功快照、仅元数据结果和失败尝试都追加记录，不覆盖旧版本。空白结构见 [来源快照模板](../templates/来源快照.md)。

## 分类维度

每条来源同时从以下维度分类：

### 内容载体 `source_kind`

- `web_article`
- `book`
- `video`
- `podcast`
- `speech`
- `conversation`
- `other`

### 来源关系 `stance`

- `pending`：使用者尚未表明态度；
- `endorsed`：认同来源的核心观点；
- `partially_endorsed`：认同其中一部分；
- `reference`：用作资料，不代表认同；
- `questioned`：主要用于质疑或反思；
- `opposed`：明确反对其核心观点。

来源级 `stance` 只是便于浏览的当前概览，必须注明统计截止时间。精确回应以数据根 `responses/` 中的时间线为准。

来源作者的观点与使用者本人的观点必须分别保存。使用者明确采用的命题才能进入其个人命题库；即便如此，引用时仍需注明原作者。

### 处理状态 `content_status`

- `registered`：只完成来源登记；
- `metadata_only`：已获得基本元数据；
- `summarized`：已完成结构与内容摘要；
- `mapped`：已提取命题并连接到思考地图；
- `cited`：已经进入某份表达成品；
- `unavailable`：当前无法读取。

### 权利状态 `rights`

- `third_party_copyright`：第三方受版权保护内容；
- `licensed`：获得明确许可的内容；
- `public_domain`：公有领域内容；
- `user_owned`：由使用者拥有版权的内容；
- `unknown`：尚未确认。

## 网络来源采集流程

1. 登记原始 URL 和带时区的访问时间；
2. 优先使用合规的页面读取工具获取元数据和主要内容；
3. 页面不可读取时，可以尝试正常浏览器访问或搜索合法转载，不绕过验证码、付费墙或安全限制；
4. 在权利允许时冻结来源快照；使用者直接提供内容时，将完整文本保存到数据根 `raw/sources/`；每个快照记录版本、获得方式、带时区的抓取时间、字节数和 SHA-256；
5. 确认最终 URL、标题、作者、平台和发布日期；
6. 识别来源载体、语言和初步主题；
到这里可以只完成来源登记和归档并结束流程。若要让来源进入个人思考流程，则继续：

7. 请使用者针对全文、章节、段落、句子或文本范围写下至少一条个人批注；
8. 将每条批注作为带时间的 `Material(MNNN)` 保存，并锚定具体来源快照与位置；
9. 对批注进行镜像确认；未经确认的批注只留在待处理素材区，不得进入正式思考地图；
10. 对已确认批注执行按需歧义检查；即将成为关键概念或命题核心词的语义必须由使用者确认；
11. 保存文章结构和详细摘要；
12. 提取关键命题、论据、反例和概念关系；
13. 保存总量有限、确有必要的短摘；
14. 请使用者分别标记共鸣、认同、采用、质疑或反对；
15. 只有使用者明确采用时，才将来源命题转化为个人命题并连接到思考地图；
16. 记录抓取失败、页面变化或链接失效情况。

来源可以只完成登记和归档，不强迫使用者立刻批注。但没有使用者批注时，它只是来源库中的资料，不能被系统视为使用者的思想，也不能仅因导入行为推断使用者认同。

## 来源批注与定位

来源批注记录的是“这份外部内容在某个时间触发了使用者什么想法”。它是使用者原话，因此使用个人素材编号 `MNNN`；来源作者原文仍属于 `SRC-NNNN`，二者不得合并。

批注可以使用以下范围：

由具体文字触发的个人思考必须绑定原句或段落；仅当回应确实针对整体时才采用 `whole_source`。不因定位困难自动降级为全文；位置未取得时明确待定位。文本定位采用 W3C Web Annotation 的目标与选择器建模方向，并额外绑定本系统不可变快照及哈希；标准兼容的软件实现仍在规划中。

- `whole_source`：整篇来源；
- `section`：一个标题或章节；
- `paragraph`：一个或多个段落；
- `text_quote`：一句话或连续文本范围；
- `page`：文档或书籍页码；
- `time_range`：音频或视频时间段；
- `region`：图片或页面中的区域。

每条批注至少保存：

- `source_id` 与不可变的来源快照版本；
- 批注范围；
- 可恢复位置的定位信息，例如标题路径、段落序号、原文精确片段及前后文；
- 使用者批注原话；
- 带时区的 `recorded_at`；
- 可选的 `effective_at` 与时间精度；思想时间未知时保持为空并标记 `unknown`；
- 隐私状态、镜像流引用和确认事件引用；当前准入状态只能作为事件派生缓存。

只记录“第 7 段”不足以长期定位，因为网页可能更新。位置必须同时绑定 `source_snapshot_id` 与快照哈希，并尽可能保存精确文本及前后文；非文本来源保存页码、时间范围或画面区域。必要短摘仍遵守引用限制；完整原文只存在数据根中的私有快照。

来源批注不等于观点回应事件。批注可能是联想、经历、问题或反对；只有使用者明确表达共鸣、认同或采用时，才另行建立相应 `RSP-YYYYMMDD-NNN` 事件。

来源中的关键词语义也必须保持归属边界：协作者可以根据上下文提出“原作者可能怎样使用这个词”，但这只是作者含义候选；使用者只能确认自己批注中的个人用法，不能替原作者确认本意。需要进入编码的个人关键词按照按需歧义检查流程建立 `TERM-NNNN/VNNN` 与语义确认事件。

## 命题归属

来源内部的命题使用以下格式：

```text
SRC-0001/P01
SRC-0001/P02
```

这些编号只表示“协作者认为原作者提出了这个观点”，不表示使用者认同。使用者明确确认后，才为其建立独立的个人命题编号，例如 `P012`，并记录它来自或受到了哪个来源命题的影响。

需要同时保留三个层次：

- **原作者观点**：来源实际提出了什么；
- **协作者分析**：我们如何概括、连接或质疑它；
- **使用者立场**：认同、部分认同、引用、质疑或反对。

## 观点回应时间线

“喜欢”“认同”和“采用”分别记录，不能相互推导：

- 喜欢一种表达，不表示同意它的判断；
- 同意一个判断，不表示要把它写进自己的作品；
- 采用外部观点，也可能是经过修改后的采用。

每次回应建立 `RSP-YYYYMMDD-NNN` 事件，并记录 `recorded_at`、`effective_at`、时间精度、当时语境和上一状态。观点变化时追加新事件，保留此前观点。

具体规则见 [观点回应时间线](./观点回应时间线规范.md)。

## 引用规范

- 引用任何外部观点时注明作者；作者未知时注明标题、平台和链接；
- 不把“用户提供了来源”写成“用户认同该观点”；
- 转述必须保持原观点的限定条件，不为方便论证而扩大结论；
- 直接摘录保持在必要的最短范围；
- 正式发表前重新检查链接、署名、发布时间和原文语境；
- 无法确认作者或出处的内容不得伪装成权威引用。

网页读取失败时，不猜测标题、作者或主要观点。先以 `unavailable` 或 `registered` 状态保存，后续通过合法可访问的页面、作者授权副本或使用者提供的内容补全。
