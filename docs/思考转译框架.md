# 思考转译框架 v0.2

> 这是一套等待真实样本验证的工作模型，不是一套要求所有思想服从的固定模板。

## 1. 编码、传递与解码

信息从一个人抵达另一个人，需要经过三个不同阶段：

```text
表达者的内在表示
        ↓ 编码
可确认的共享语义表示
        ↓ 传递
保持版本、语境与完整性的信息包
        ↓ 解码
适合具体接收者思路的沟通表示
        ↓
接收者形成的实际理解
```

### 1.1 编码

编码发生在表达者一侧。它把感觉、记忆、碎片、判断和矛盾转换成结构化语义，同时保留原始素材、来源归属、不确定性和表达者确认状态。

编码结果应尽可能连接到可追溯的共享语义锚点，使不熟悉表达者私人语境的人也能理解关键概念。共享语义锚点可以来自标准、权威定义、领域共识或稳定的常用含义；存在多种解释时必须并列呈现，不能伪造共识。

表达者的个人含义不会被公共定义覆盖。系统需要同时保存“这个词通常是什么意思”与“表达者此刻用它具体指什么”，并明确二者的差异。

### 1.2 传递

传递负责让已经编码的含义跨越通道到达另一端。它保存信息包的版本、语境、隐私、来源和完整性，不负责猜测接收者会怎样理解，也不负责针对接收者改写内容。

序列化格式和传输通道可以改变封装形式，但不得静默改变已经确认的语义内容。

### 1.3 解码

解码发生在接收者一侧或面向接收者的适配层。它依据具体接收者已经知道什么、如何理解关键词、习惯怎样组织因果与先后关系，以及当前媒介允许怎样反馈，将共享语义表示转换成对方更容易准确进入的表达。

接收者模型只使用明确资料和可校准假设，不能把对方的动机、人格或心理状态当成已知事实。

这里描述的是语义职责，不是固定的部署时序。解码既可以在收到 `SemanticPacket` 后运行，也可以由发送侧服务预先生成接收者适配的沟通表示，再交给物理通道发送；无论部署在哪里，适配都属于解码，并且必须能够回溯到原编码版本。

### 1.4 当前产品边界

当前软件开发重点是编码：先形成忠实、可追溯、可以由表达者确认的共享语义表示。传递阶段只先定义稳定的数据契约与完整性边界；解码以及接收者适配在编码闭环稳定后开发。

人工协作可以暂时完成全流程，但不能把人工可做误写为软件已经实现。

编码内部当前只推进前两步：

| 协作步骤 | 当前结论 |
| --- | --- |
| 忠实采集 | 已确认双路径：直接输入，或外部来源快照上的使用者批注 |
| 镜像确认 | 已确认是进入思考地图前的必要校准 |
| 语义澄清 | 开放设计问题，必要性与触发方式继续讨论 |
| 思考建模 | 保留既有框架，等待前序机制稳定 |
| 接收者建模至输出回收 | 暂缓细化 |

## 2. 三种表示

一次完整转译包含三种不同表示：

### 2.1 内在表示

思考最初存在的形态：片段、感受、画面、记忆、身体反应、未完成判断、矛盾和联想。

内在表示不必符合语言逻辑。它需要被忠实保存，而不是立即修正。

直接输入本身就是内在表示的材料。外部文章等来源本身不是表达者的内在表示；表达者对全文或具体位置写下的批注才是个人材料。两种材料都保存录入时间与思想所属时间。

### 2.2 共享语义表示

经过镜像确认、必要时的澄清和后续编码形成的思考地图或 `SemanticPacket`，包括核心问题、命题、概念含义、共享语义锚点、个人语义差异、支持材料、反例、因果假设、矛盾和未知项。

语义表示用于检查“我到底想表达什么”，但通常还不是适合直接发给他人的文本。

### 2.3 沟通表示

解码阶段根据接收者、关系、目的、媒介和风险生成的实际表达。它可以调整顺序、长度、语气、例子和解释深度，但不能悄悄改变已经确认的核心含义。

## 3. 转译管线

```text
直接输入 ───────────────────────────┐
外部来源快照 → 使用者定位批注 ─────┴→ 带时间的原始素材
   ↓ LLM 镜像候选
   ↓ 表达者确认、纠正或拒绝
已确认材料
   ↓ 若后续确认需要，则进行按需歧义检查
   ↓ 命题/概念/关系建模
   ↓ 共享语义锚定 + 个人差异保留
共享语义表示（编码结果）
   ↓ 版本、语境与完整性封装
可传递信息包
   ↓ 接收者建模 + 表达策略（后续解码）
沟通表示
   ↓ 表达者校准 + 接收者理解反馈
可使用的表达与实际理解
```

任何阶段发现失真，都可以回到上一个阶段，而不是继续润色错误的版本。

## 4. 语义地图的基本元素

- **素材**：表达者实际提供的片段；
- **来源批注**：表达者针对某个不可变来源快照及具体位置写下的个人思考；
- **命题**：表达者可能正在提出的判断；
- **证据**：支持命题的观察、经历或资料；
- **反例**：限制或挑战命题的材料；
- **概念**：关键词对表达者的个人含义；
- **共享语义锚点**：可追溯的常用、标准或领域解释；
- **个人语义差异**：表达者用法与共享解释之间的差异；
- **关系**：支持、因果、递进、冲突、条件或例外；
- **未知项**：当前无法确认但会影响表达的内容；
- **表达意图**：希望对方真正理解的核心；
- **边界**：不愿表达、不适合表达或无法确认的内容。

## 5. 个人语言档案

每个人都会反复使用一些具有私人含义的词语。框架可以逐步记录：

- 某个词对表达者具体意味着什么；
- 哪些词容易让表达者感到被误解；
- 表达者习惯使用怎样的比喻、节奏和叙述顺序；
- 哪些措辞虽然正确，却不像表达者本人；
- 表达者如何区分看似相近的概念。

个人语言档案用于提高忠实度，不能被用来把一个人的未来表达固定成过去的样子。

## 6. 接收者模型

同一编码结果面对不同对象可能需要不同的解码方式。接收者模型属于后续解码阶段，至少包含：

- 对方与表达者的关系；
- 对方已知和未知的信息；
- 双方对关键词可能存在的含义差异；
- 对方可能优先关注的内容；
- 当前媒介允许的长度、反馈和修正空间；
- 表达可能产生的现实后果。

接收者模型只能描述合理预期，不能假装知道对方真实的内心活动。

## 7. 表达策略

根据任务选择不同策略：

- **高密度**：适合已有大量共同背景的接收者；
- **补充语境**：适合双方背景不对称的情况；
- **事实优先**：先建立共同观察，再给出个人解释；
- **感受优先**：重点让对方理解表达者的内在体验；
- **探索式**：保留疑问，邀请对方共同澄清；
- **立场式**：明确观点、理由、边界和希望采取的行动；
- **叙事式**：通过场景和变化过程传达难以抽象概括的思想。

策略改变表达形式，不应暗中改变事实和核心立场。

## 8. 双向校准指标

### 表达者侧

- 忠实度：核心含义是否得到保留？
- 完整度：重要部分是否缺失？
- 强度：语气是否比原意更强或更弱？
- 归属感：表达者是否仍然认得自己的声音？

### 接收者侧

- 可复述性：对方能否准确说出核心意思？
- 歧义风险：哪些词最容易产生另一种解释？
- 语境充分性：对方是否拥有理解所需的背景？
- 行动清晰度：如果期待回应或行动，是否表达明确？

现阶段这些指标以质性检查为主，不伪造没有经过验证的精确分数。

## 9. 框架验证

每次真实使用后记录：

- 哪个问题帮助表达者发现了新的含义？
- 哪一步制造了负担或打断了思考？
- 哪个候选表达最接近本人，为什么？
- 实际接收者产生了什么误解？
- 误解来自思想尚未澄清、共同语境不足，还是表达策略不合适？
- 失真发生在编码、传递还是解码阶段？
- 有哪些无法进入当前模型的重要内容？

框架应被样本修正，而不是让样本服从框架。

## 10. 时间维度

思考转译不只发生在人与人之间，也发生在同一个人的不同时间之间。

今天的表达者可能已经无法完全进入过去的语境，也可能会用后来形成的概念重新解释当时的自己。因此，框架同时保存：

- 当时的原始表达；
- 系统实际录入时间 `recorded_at`；
- 思想所属时间 `effective_at` 及时间精度；
- 当时对某个观点的共鸣、认同和采用状态；
- 后续发生的立场变化；
- 今天对过去观点的理解。

观点变化不是需要清理的数据冲突，而是长期思想记录的重要内容。当前观点应被视为带有 `as_of` 时间的快照，不能取代完整时间线。
