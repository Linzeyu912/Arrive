# ARRIVE 后端架构 v0.1

## 目标

后端的第一职责不是生成漂亮文本，而是可靠地保存思想形成和转译的过程，并把项目协议变成数据库可验证的不变量。

当前版本实现一个可运行的模块化单体。它适合早期快速验证；当来源抓取、模型推理和表达生成需要独立扩展时，再拆分后台任务与模型服务。

## 技术选择

- Python 3.12
- FastAPI：REST API 与 OpenAPI 文档
- Pydantic：输入边界和跨字段验证
- SQLAlchemy 2：持久化抽象
- Alembic：数据库迁移
- SQLite：本地默认数据库
- PostgreSQL：后续多人和生产环境目标
- Pytest：领域行为和 API 验证

SQLite 只是本地默认值。模型没有依赖 SQLite 特有查询，但多写入者部署前需要把回应事件编号分配改为数据库序列或锁，并在 PostgreSQL 上验证迁移。

## 模块边界

```text
HTTP / OpenAPI
      ↓
Pydantic schemas
      ↓
Application services
      ↓
Domain invariants
      ↓
SQLAlchemy models
      ↓
SQLite / PostgreSQL
```

- `api.py`：HTTP 路由，不承载领域判断；
- `schemas.py`：外部输入、枚举和结构校验；
- `services.py`：编号、目标解析、追加事件和时间快照；
- `domain.py`：协议中的稳定词汇；
- `models.py`：数据库结构和唯一性约束；
- `serializers.py`：持久化对象到 API 表示的显式转换；
- `migrations/`：可审计的数据库演进历史。

## 核心数据模型

| 实体 | 稳定 ID | 作用 |
| --- | --- | --- |
| `Material` | `M001` | 保存原始思绪、感受、经历、矛盾或问题 |
| `Source` | `SRC-0001` | 保存外部来源身份与权利信息 |
| `SourceProposition` | `SRC-0001/P01` | 保存归属于来源的命题 |
| `PersonalProposition` | `P001` | 保存使用者明确采用或独立形成的命题 |
| `ResponseEvent` | `RSP-YYYYMMDD-NNN` | 追加共鸣、认同和采用变化 |
| `ThoughtMap` | `MAP-0001` | 保存命题、问题、概念、边界及其关系 |

## 时间模型

每个观点回应保存两份时间表示：

- 原始 ISO 8601 字符串：保留表达者提供的时区和时间形状；
- UTC epoch milliseconds：用于跨时区排序和 `as_of` 查询。

`recorded_at` 表示系统实际记录时间，`effective_at` 表示观点所属时间。二者分开后，可以在今天补录几年前的思想，而不会假装它今天才出现。

## 观点快照算法

共鸣、认同和采用是三条独立事件流。查询某个时间点的状态时：

1. 只选择 `effective_at <= as_of` 的事件；
2. 按有效时间、记录时间和内部 ID 排序；
3. 分别折叠三个维度；
4. `unspecified` 或 `undecided` 表示本次事件不修改该维度；
5. 返回每个维度的值、来源事件和生效时间。

因此，一次只更新“认同”的新事件不会意外清空此前的“共鸣”。

## 追加式历史

API 没有回应事件的更新和删除路由。观点变化通过创建新事件并填写 `supersedes` 表示。

数据库同时约束：

- 事件公开编号唯一；
- 同一天的事件序号唯一；
- `supersedes` 必须指向已有事件；
- 应用层要求新旧事件指向同一命题。

这不是完整的通用事件溯源系统，只对最需要保存变化的“观点回应”采用追加式模型。

## 来源与个人观点边界

来源命题不会因为使用者阅读或喜欢而自动成为个人命题。只有明确创建个人命题，或在 `adopt`、`adapt` 回应中提供个人命题文本，系统才建立 `P001` 等个人编号，并保存来源关系。

原始第三方全文不进入数据库。数据库只保存本地私密档案的相对路径、字节数和 SHA-256；实际全文继续留在不受 Git 跟踪的私密目录。

## 思考地图

思考地图允许保存矛盾，不要求形成树形结构。当前以经过验证的 JSON 节点和边存储，便于快速调整模型。应用层保证：

- 节点 ID 在单张图中唯一；
- 关系的两端必须存在；
- 不接受节点到自身的关系；
- `contradicts` 是一等关系，不会被自动消解。

当跨图查询和大型图遍历成为真实需求后，再将节点与边拆成关系表或图数据库；当前不提前引入复杂基础设施。

## 隐私与部署边界

当前 MVP 尚未实现账户认证、授权、字段级加密、审计日志和密钥管理，因此：

- 只在本机或受控的私有网络中运行；
- 不得直接暴露到公网收集真实私人思绪；
- 不要把反向代理认证误认为完整的数据授权模型；
- 在实现多用户之前，所有表默认属于单一使用者。

进入可部署阶段前至少需要：

1. 用户和工作空间边界；
2. 每条记录的所有权与访问控制；
3. 静态和传输加密；
4. 敏感字段日志脱敏；
5. 数据导出、删除和保留策略；
6. 来源抓取的版权、robots 与失败处理策略；
7. PostgreSQL 并发和备份验证。

## 模型服务边界

未来的大语言模型只作为“候选理解与候选表达”提供者，不能直接修改已确认命题。模型输出必须保存：

- 输入材料引用；
- 使用的提示或流程版本；
- 模型和配置版本；
- 输出时间；
- 内容类型：归纳、推测、问题或候选表达；
- 使用者确认状态。

模型提供者应通过接口适配，领域数据不绑定某一家服务。

## 下一纵向切片

下一阶段建议实现“表达任务”：

```text
素材 + 思考地图 + 接收者模型
              ↓
        候选表达版本
              ↓
   表达者校准 + 接收者校准
              ↓
          最终输出
```

对应实体包括 `ExpressionTask`、`AudienceModel`、`DraftVersion` 和 `CalibrationEvent`。它们也应采用版本追加方式，避免候选文本覆盖作者原意。
