# 感情分析框架 v0.1

> 当前版本是一套待验证的工作假设。它会随着真实素材的增加持续修订。

## 1. 分析单位

框架以“具体事件”为基本单位，而不是直接分析“一个人是什么样的人”。

一个事件可以是一场对话、一次冲突、一段疏远、一个决定，或者一个在多年后仍然反复出现的瞬间。事件应尽可能具备时间、人物、行为和结果。

## 2. 九层分析

### 2.1 情境

当时处于怎样的关系阶段？有哪些现实限制、权力差异、文化背景和未说出口的前提？

### 2.2 可观察事实

如果由摄像机记录，它能够看到或听到什么？只记录行为、原话和明确结果，暂不解释动机。

### 2.3 当时的解释

当时的“我”如何解释这些事实？我认为对方为什么这样做，又认为这说明了什么？

### 2.4 情绪与身体反应

我感受到什么？这些感受在身体上如何出现？需要允许多种甚至矛盾的情绪同时存在。

### 2.5 需要、期待与价值

哪些需要没有被满足？哪些期待从未说出口？这件事触碰了我怎样的价值观或自我想象？

### 2.6 行动与保护策略

我做了什么或没有做什么？这种行动试图保护什么？它在短期和长期分别带来了什么？

### 2.7 其他可能的解释

在不否定自身感受的前提下，还有哪些合理解释？哪些解释有证据，哪些只是猜测？

### 2.8 重复模式

类似的情境、情绪或行动是否在其他关系中出现？共同点是什么，差异又是什么？至少出现两次后，再暂时称其为模式。

### 2.9 今天的回望

现在的我如何理解当时的自己？哪些判断改变了，哪些仍然成立？如果重新面对，我想做出怎样的选择？

## 3. 四种内容必须分开

| 类型 | 定义 | 示例 |
| --- | --- | --- |
| 事实 | 可直接观察或核实的内容 | “对方三天没有回复消息。” |
| 解释 | 对事实含义或动机的判断 | “对方不在乎我。” |
| 感受 | 自身的情绪和身体体验 | “我焦虑、愤怒，也感到羞耻。” |
| 需要 | 希望被满足的关系或价值需要 | “我需要确定感和被认真回应。” |

这四者可能互相影响，但不应彼此冒充。例如，“我感到被操控”包含了对他人动机的解释；可以进一步拆成具体行为、自己的解释和由此产生的感受。

## 4. 分析关系，而非诊断人物

框架关注具体行为、互动循环和现实后果。除非有合格专业人员的正式诊断与使用许可，不使用人格障碍、精神疾病等标签解释他人。

可以写：

> 当我追问时，对方沉默；对方沉默后，我更加急切地追问，最终双方都退出了对话。

不宜仅凭叙述写：

> 对方就是某种人格，所以一切都可以由这个标签解释。

## 5. 从分析到叙事

分析的结果不应原封不动地倾倒进文章。转化为叙事时，依次寻找：

1. 一个能够承载问题的具体场景；
2. 当时的我相信什么；
3. 这个信念如何影响选择；
4. 事件怎样打破或强化了它；
5. 今天的我如何重新理解这段经历；
6. 仍然没有解决的部分是什么。

一篇有力量的自传式思考不一定给出标准答案，但应让读者看见认识是怎样发生变化的。

## 6. 框架验证问题

每处理一批新经历，都应检查：

- 哪些问题确实帮助作者看见了新东西？
- 哪些问题只是重复描述，没有推进理解？
- 框架遗漏了哪些现实因素？
- 框架是否诱导作者过度解释对方动机？
- 是否存在无法放进九层模型的重要内容？
- 新发现是个人特例，还是可能具有可迁移性？

验证结果应推动框架升级，而不是强迫素材适应框架。
