# 数据目录规范

本文定义仓库外 `ARRIVE_DATA_DIR` 的逻辑结构。它描述数据如何组织，但不在软件仓库保存任何真实样本。

## 目录

| 目录 | 内容 |
| --- | --- |
| `raw/` | 不可改写的原话、导入原文、附件及完整性信息 |
| `inbox/` | 尚未整理的片段、感受、矛盾、联想和问题 |
| `materials/` | 获得稳定编号的素材 |
| `sources/` | 外部来源身份、摘要、命题和索引 |
| `responses/` | 共鸣、认同和采用的追加式事件 |
| `thought-maps/` | 命题、问题、边界、矛盾及其关系 |
| `drafts/` | 候选结构、候选表达和中间版本 |
| `decisions/` | 从真实协作产生的决定时间线 |
| `outputs/` | 经使用者确认的个人表达成品 |
| `database/` | 应用数据库和本地索引 |
| `exports/` | 有明确目的地、等待审阅或临时生成的导出 |

## 稳定编号

- 原始素材：`MNNN`；
- 个人命题：`PNNN`；
- 问题：`QNNN`；
- 接收者假设：`ANNN`；
- 表达草稿：`XNNN`；
- 决定：`DNNN`；
- 外部来源：`SRC-NNNN`；
- 来源命题：`SRC-NNNN/PNN`；
- 观点回应：`RSP-YYYYMMDD-NNN`。

编号分配后保持稳定。更正、观点变化和草稿迭代通过追加版本表达，不重排编号或覆盖历史。

## 隐私与可分享性

- `private`：只用于本人理解；
- `anonymized`：完成去标识处理后可作为分享候选；
- `shareable`：内容所有者确认其可作为分享候选。

三个等级都属于数据，默认留在 `ARRIVE_DATA_DIR`。实际对外发送仍需按具体版本、接收者和渠道再次确认。

完整边界见 [软件与数据隔离规范](./软件与数据隔离规范.md)。来源和回应的字段规则分别见 [外部来源管理规范](./外部来源管理规范.md) 与 [观点回应时间线规范](./观点回应时间线规范.md)。
