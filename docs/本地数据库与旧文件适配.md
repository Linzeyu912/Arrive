# 本地数据库与旧文件适配

前端通过现有后端读取本地 SQLite，不直接访问磁盘。默认数据库为项目内 `arrive-data/database/arrive.db`；配置了 `ARRIVE_DATA_DIR` 时使用对应数据根。Docker 必须挂载同一数据目录才能看到同一份记录，不会自动寻找其他数据库并合并。

## 使用方式

1. 启动后端：先执行数据库迁移，再扫描数据根内的旧 Markdown 文件。
2. 打开首页：“本地已保存”自动读取素材、来源数量及最近来源，保存新素材后自动更新。
3. 在“来源”查看已适配的来源卡和明确归属于来源的命题；在“本地档案”展开旧文件原件。
4. “刷新”重新查询数据库。运行期间新增或修改旧文件，需要重启后端触发适配；当前没有文件实时监视器。

## 适配范围

- 扫描 `sources/`、`materials/`、`inbox/`、`responses/`、`decisions/`、`thought-maps/`、`drafts/` 下 UTF-8 `.md`，跳过 INDEX 和 README。
- 将来源卡的 `id/source_id`、`original_url/url`、`authors`、`classification` 等旧字段映射到现有来源模型，保留来源编号。
- 明确的“原作者命题”表格以协作者归纳归属导入，保留命题编号，不自动生成个人命题或回应事件。
- 来源卡引用的快照会核对来源与快照编号，并校验原始附件的字节数和 SHA-256（有声明时）；附件留在原位置，本轮没有新增全文预览接口。
- 其他旧记录保存为只读原件档案。尚未完成素材、决定、回应、镜像、语义确认等旧格式到当前领域模型的通用转换，不能以档案存在代表编码流程完成。

## 保留与冲突

`legacy_documents` 保存旧文件内容、相对路径、SHA-256、适配状态及带时区的入库时间和 UTC 毫秒值。文件相对路径与哈希共同唯一；相同文件重复启动不产生重复记录。文件变化保留新档案版本；来源编号冲突不会覆盖现有来源，标记待核对。当前没有自动合并或解决冲突的接口。

已知原始带时区时间保留原表示。原录入时间未知时，来源的登记时间使用本次导入时间，并在档案中明确说明；日期、发布时间和文件修改时间不作为个人思想发生时间。原始元数据始终可在原件中核对。

不兼容元数据及附件校验失败保留为待核对档案；非 UTF-8 文件及逃逸数据根的文件链接不读取。当前档案列表没有分页，适用于小型本地库；大量档案的启动扫描、分页和更细的错误报告仍需后续完善。

升级前应备份数据库；本次本地升级已用 SQLite 备份接口在数据根 `backups/` 生成备份。源文件未修改，数据和备份仍由 Git 忽略。API 仅提供 `GET /api/v1/local-records` 和 `GET /api/v1/local-records/{id}`，无修改或删除档案接口。当前后端无认证与字段加密，继续仅用于本地或受控环境。
